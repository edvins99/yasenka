# ReplyQuest Design Principles

1. **Save time first.** A feature belongs in ReplyQuest only when it reduces repetitive work or improves draft quality.
2. **The user stays in control.** ReplyQuest prepares drafts; the user reviews and publishes.
3. **Never auto-post.** No automatic Send, likes, follows, reposts, bookmarks, or account actions.
4. **One clear workflow.** Select post → choose tone → review drafts → copy or insert → send manually.
5. **Simple before clever.** Reliable post detection and useful drafts matter more than animation, gamification, or novelty.
6. **Context over templates.** Replies should reference the actual post and campaign rather than repeat generic hype phrases.
7. **Variety without impersonation.** Offer distinct tones, but do not claim to be the user or fabricate personal experiences.
8. **Local-first and transparent.** Store configuration and history locally. Explain when text is sent to an external AI provider.
9. **Fail safely.** When X markup changes or AI generation fails, show an error and do nothing to the account.
10. **Editable by the user.** Campaigns, accounts, tones, and personal guidance must be configurable without code changes.
11. **No fake certainty.** Do not invent project facts, partnerships, metrics, or claims absent from the post or configured context.
12. **Isolation.** ReplyQuest remains a separate experiment and must not be mixed with the user's primary Codex project.
