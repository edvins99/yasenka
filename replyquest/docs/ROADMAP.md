# ReplyQuest Roadmap

## Sprint 1 — Reliable local MVP

Goal: make the existing prototype useful on real X posts.

- detect author handle, post ID, URL, and visible post text;
- match posts against editable campaign accounts;
- select a post and choose Quick, Natural, or Insight;
- produce three distinct drafts;
- copy or insert a draft into the native reply composer;
- never click Send;
- store completed post IDs locally;
- test manually on Yellow and Midnight accounts.

## Sprint 2 — AI provider and prompt quality

- provider settings with local secret storage;
- clear permission before sending post text externally;
- campaign-specific instructions;
- Latvian and English interface support;
- duplicate and cliché detection;
- graceful offline and provider-error states.

## Sprint 3 — Reply queue

- collect visible matching posts into a local queue;
- campaign and priority filters;
- next / skip / done navigation;
- daily progress counters;
- prevent duplicate work across sessions.

## Sprint 4 — Personal adaptation

- editable personal style notes;
- optional examples for different reply modes;
- learn only from replies the user explicitly saves;
- length and tone controls;
- reusable custom campaign profiles.

## Later, only after MVP proves useful

- quote-post drafts;
- original-post drafts;
- import and export of campaign configuration;
- broader browser support;
- optional non-distracting companion UI.

## Success metric

The MVP succeeds when routine ambassador replies take materially less time while every published reply is still reviewed and sent by the user.
